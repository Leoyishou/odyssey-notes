> 1. 上限：原生 GUI 模型 > 写代码 > 无障碍树 > OCR
> 2. 在 Mac 上让 agent 操作应用时，可以按这个顺序：
> 	1. **应用有脚本接口或命令行**：让 agent 写 AppleScript 或 Shell，最稳。
> 	2. **没有接口**：用 AppleScript 的 System Events，或者 agent-desktop，读界面结构来> 操作。
> 	3. **界面结构也读不到**：最后再用看截图的方案（Codex Computer Use、UI-TARS）。

# 🪞Notes


| 工具                          | 上限卡在哪                                                | 上限高低                                       |
| --------------------------- | ---------------------------------------------------- | ------------------------------------------ |
| **UI-TARS**（原生视觉 GUI 模型）    | **模型能力**。屏幕上看得见的东西都能操作，模型越强它就越强                      | ⭐⭐⭐⭐⭐ 最高，而且会随着模型进步继续往上涨                    |
| **Open Interpreter**（写代码执行） | **这个 APP 有没有 API 或命令行可用**。能用代码做的事，它又快又稳；碰到只能点界面的就没办法 | ⭐⭐⭐⭐ 在代码能覆盖的范围内最高，但覆盖不了纯界面操作               |
| **agent-desktop**（读无障碍树）    | **这个应用的无障碍信息做得好不好**。这是应用开发者决定的，模型再强也突破不了             | ⭐⭐⭐ 下限高、很稳，但上限是固定的                         |
| **OmniParser**（截图解析）        | **检测模型的识别准确率**，加上它这种"先解析再决策"的两步结构（类似先 OCR）           | ⭐⭐ 我**猜**它长期会被淘汰：视觉模型自己就能精准定位以后，中间这层解析就多余了 |
| **Cua**（沙盒环境）               | 它不限制能力，只决定在哪里跑                                       | 不适用，和谁搭配都行                                 |
