# 🪞Notes

1. **[[OSS]] 是存储，不是数据库**：它只能按 key 存取整个文件，没有查询、索引和事务。它相当于"云上的无限硬盘"。
2. **真正算"[[数据库@]]"的**：MySQL、Redis，以及勉强算上的 [[Workers KV]]（更准确的叫法是"KV 存储服务"）。
3. **Hive 是计算/查询层，不是存储**：数据实际放在 OSS 或 [[HDFS]] 上，Hive 负责"把文件当表来查"。

| 名称 | 类别 | 本质 | 典型用途 |
| --- | --- | --- | --- |
| MySQL | 关系型数据库（OLTP） | 按表、行、列存数据，支持 SQL 和事务 | 业务主库，比如用户和订单 |
| Redis | 内存 KV 数据库（NoSQL） | 数据放在内存里，按 key 取 value，速度极快 | 缓存、会话、计数器、排行榜、分布式锁 |
| Workers KV | 边缘 KV 存储（Cloudflare 托管服务） | 全球分布的 KV，最终一致：写入后大约 60 秒才同步到全球。适合读多写少 | 配置、功能开关、边缘缓存 |
| OSS | 对象存储（不是数据库） | 存放"文件或二进制大对象"，路径加文件名就是 key，不能查询文件内容 | 图片、视频、备份、日志，也可以做数据湖底座 |
| Hive | 数据仓库 / SQL 查询引擎（本身不存数据） | 把 HDFS 或 OSS 上的文件"映射成表"，用类 SQL 做批量分析 | 离线大数据分析、报表 |
