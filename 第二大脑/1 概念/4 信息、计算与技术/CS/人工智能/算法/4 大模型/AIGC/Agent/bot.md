#  💡Summary  

> [!Info]
> 连续、高效、主动、持久
> - relay
> - 多设备互动
> - 去 Session 化（bot）
> 

为了不掉线，计算、状态、执行环境三件事拆开。

1. Agent 的“脑子”在云端，
2. 聊天记录存数据库，
3. 代码文件留在你电脑上，通过一个后台小程序连过去。
4. 外面还放了一个 Watchdog，像独立巡检员，定期查各个 Worker 有没有卡住跑偏，有问题就介入。

现场可达：比如 Hindsight 在你 Mac 本机的 8890 端口——本机 Agent 能用，云 Agent 在别人的机器上，连不到你电脑这个口，对它来说这个「现场」就不可达。技能装好了、密钥也注入了，这一步仍然会断。所以它不是第三种「能力文件」，而是问：这个 Agent 站的位置，够不够得着它要用的东西。 够不着就要另造端点（公网/隧道/云上的同款服务），不能假装复制技能就等于现场也搬过去了。

Bot 和人一样，在一个岗位上是会有退休的时候的，需要用一种 AI 尺度去感知这个退休的时间。做好记忆，也就是文档的沉淀和目的的交接。 这个背后的本质，其实还是目前的最好的模型的上下文只有 1000K。

Proactive = [[定时任务]] + [[事件]]驱动

1. 感觉 bot 的本质是 agent上面封装一层记忆系统，实现不切 session 的无限上下文的单 agent 的使用体验
2. 规则
	1. 做事前之前自己一个 DDL 并 hook 出一个后面的回看任务
3. 启动 [[subAgent]] 时候用的命令
	1. codex --dangerously-bypass-approvals-and-sandbox
	2. dsh 把「沙箱模式」和「审批策略」分成两个旋钮：沙箱有 `workspace-write`、`danger-full-access` 等，审批有 `ask`（要确认）和 `never`（不确认）。权限预设插件 `@deepseek-ai/dsh-permission-presets` 默认就带两档：`

1. 工作方式：你是对接人，不是具体干活人。别自己干活，都开subagent，subagent都用6.1sol 中等 fast。 什么时候不开**  一两句闲聊、确认、改口——父 agent 自己回。超过两轮工具 / 会占屏 / 要并行，才开。否则又慢又贵。「只有你跟我说话；subagent 不准直接回我，做完只回报给你。」不然会刷屏、抢话。 给 subagent 起角色，别开匿名工**  派活时写清成功标准和 DDL（分钟级），别只说「去做」。 停与复用**  ：「我说停就杀掉所有子任务；同一件事优先 resume 闲着的，不要无限新开。」
   
   
2. 事事有回应，敢为极致。做任务前从AI而不是人的角度，预估一下结束时间，设置hook，到期检查。时间设置要激进，敢为极致。
